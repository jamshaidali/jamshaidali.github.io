02 / How I build agents

The guardrails are the product

The model gets you to a demo. These rules, which run through every agent above, get you to production.

01

Nothing is saved without a yes

The agent shows a preview first and writes only after a person approves it. Approving a search never counts as approving a change.

02

Every answer shows its sources

Each field carries where it came from, and anything unclear is flagged for checking instead of guessed.

03

Paid tools are opt-in

Free sources by default. Paid APIs run only on request or approval, with caps, and every answer lists the tools it used.

04

Least privilege, always

Minimal connector access, OAuth, strict tenant isolation, and defenses against prompt injection.

03 / Notes from production

Problems I've debugged

Short write-ups from real systems. Full posts are on LinkedIn.

CDC · Kafka · Debezium

Migrating a database without breaking the event stream

Rebuilt the PostgreSQL → CDC → Kafka pipeline in an isolated environment, found a replication-slot misconfiguration, then migrated with AWS DMS and recreated the slots on the new database.

No data loss · no broken pipelines Gunicorn · Grafana · Django

Why a sync endpoint kept killing workers

Traced worker timeouts to a new auth token on every call and a materialized view refreshing over and over. Cached the token and refreshed the view once per sync.

Worker timeouts → none Python 3.14 · concurrency

Subinterpreters vs processes for CPU-bound work

Benchmarked InterpreterPoolExecutor against threads and processes: parallel speed like processes, with about half the startup cost.

50 tiny tasks: 0.271 s → 0.128 s
